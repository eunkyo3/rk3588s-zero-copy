# B와 C의 동등성 (M1-4)

PROTOCOL §11.1과 §11.2를 현재 적용되는 기준, 즉 [AMENDMENTS A5](../../prereg/AMENDMENTS.ko.md)의 기준으로 판정했다. 영문판과 다르면 영문판을 따른다.

- **A5 기준으로는 B와 C가 동등하다.** 여섯 조건이 모두 통과하고 `tools/equivalence_check.py`의 종료 코드는 0이다.
- **등록 기준으로는 동등하지 않다.** 테두리 검사를 뺀 모든 조건이 실패한다. §11.3과 A5의 마지막 항목에 따라 리포트에 이 사실을 밝힌다.

실행 정보:

- **어디서:** 보드에서 2026-11-02T01:11:23Z, 코드 커밋 `669fb9b`, 적용 중인 변경은 A6이다.
  - 최종 코드는 판정과 래퍼의 오류 경로만 다르다. 리포트와 JSON을 쓰는 순서, 그리고 래퍼의 종료 코드다.
  - 최종 판정 도구로 이 실행을 다시 판정해도 같은 `check.txt`가 나온다.
- **거버너:** 기본값. M1-3에서 아직 클럭을 고정하지 않았다.
  - 이 실행의 `env.txt`에는 policy 0(cpu0–3)의 최소 클럭이 1.8 GHz로 기록돼 있다. 다른 두 실행에서는 기본값인 408 MHz였다. 원인은 모른다.
  - 덤프는 cpu4–7에서 돌고, 세 실행 모두 같은 바이트를 냈다.
- **입력:** 영상 ①(Pexels 36330861)의 처음 1,000프레임을 `file_source`로 읽었다.
- **출력:** [results/equivalence/20261102T011123Z/](../../results/equivalence/20261102T011123Z/)에 있다. 판정 출력은 [check.txt](../../results/equivalence/20261102T011123Z/check.txt)다.
- **함께 보관한 실행** ([결과 검증](#결과-검증) 참고):
  - `20261102T011343Z`: 같은 코드로 반복한 실행이다.
  - `20261102T004513Z`: 리뷰 반영 전 도구(코드 `958641b`)로 한 실행이다. 이 실행으로 대체됐다.

## 방법

| 도구 | 하는 일 |
|---|---|
| `tools/equivalence_dump` | 각 프레임을 `h264_rkmpp`로 한 번 디코딩해 C, B, R에 넘긴다. 셋은 각자 컨텍스트 3개를 쓴다. 모든 프레임을 NPU 코어 0에서 돌리고 공용 후처리(신뢰도 0.25, NMS 0.45)를 거친 뒤, 프레임마다 입력 텐서 전체와 검출 결과를 기록한다. |
| `tools/equivalence_check.py` | 그 파일들만으로 두 수준을 모두 계산하고, 등록 기준과 A5 기준의 판정을 출력한다. 종료 코드는 A5를 따른다. |
| `tools/equivalence.sh` | `collect_env.sh`, 덤프, 판정을 차례로 실행한다. 텐서(3 × 1.2 GB)는 저장소에 넣기에 너무 커서 SHA-256 해시만 `tensors.sha256`에 남긴다. |

- **R**은 B의 전처리를 보정 없는 `INTER_LINEAR`로 바꾼 것이다. §8이 허용하는 다른 선택이다(A5). B는 실제 쓰는 그대로, 휘도 박스를 한 픽셀 옮긴 `INTER_AREA`다(A4).
- **하네스 검사:** C, B, R 각각에 대해 100번째 프레임마다와 마지막 프레임(11프레임)에서 했고, 둘 다 성립했다.
  - NPU 코어 1과 2의 출력이 코어 0과 같다. 파이프라인은 프레임을 세 코어에 나눠 보내지만, 이 도구는 코어 0만 쓴다.
  - 바인딩된 출력이 같은 텐서에 대한 `rknn_outputs_get`과 같다(A3).
- **매칭:**
  - 프레임과 클래스마다 IoU에 대한 헝가리안 알고리즘으로 짝짓는다.
  - 풀기 전에 0.5 미만의 IoU를 0으로 둔다. 그러면 짝이 될 수 있는 쌍(IoU ≥ 0.5)의 IoU 합을 최대로 만든다. IoU를 그대로 쓰면 0.5 이상인 짝 하나 대신 0.5 미만인 짝 둘을 고른 뒤 둘 다 버릴 수 있다.
- **float32:** 점수와 좌표는 읽을 때 float32로 반올림한다. 후처리가 내는 값의 형식이다. 0.25 ± 0.02 구간의 경계도 float32다.
- **종료 코드:** 0은 통과, 1은 실패, 2는 입력 불일치나 판정을 끝내지 못한 경우다. 래퍼는 판정 전 단계가 실패하면 3으로 끝난다.
- **테스트:** `tests/test_equivalence_check.py`
  - 헝가리안 풀이를 무작위 행렬 500개에서 전수 탐색과 비교하고, 탐욕적 매칭과 결과가 다른 경우를 확인한다.
  - IoU 0.5 마스킹을 확인한다.
  - 임계값 근처 제외를 양방향으로 확인하고, JSON을 거친 뒤 구간 경계에서도 확인한다.
  - A5 조건이 하나씩만 실패하는 경우, 입력 불일치, 도구 오류를 확인한다.

## 결과 검증

- **반복성:** [20261102T011343Z](../../results/equivalence/20261102T011343Z/)는 같은 코드로 다시 실행한 것이다.
  - `tensors.sha256`이 판정 실행과 같다. 즉 텐서 파일 세 개가 바이트 단위로 같다.
  - 검출 줄도 같고, `check.txt`도 같다.
  - 대체된 실행 `20261102T004513Z`도 텐서 해시와 검출 줄이 같다. `check.txt`는 코드 커밋만 다르다.
  - 계산은 결정적이고, 클럭은 값이 아니라 시간만 바꾼다. M1-3의 클럭 고정이 이 결과를 바꿀 것으로 보지 않는다.
  - `freeze-m1` 전에 B나 C의 코드가 바뀌면 다시 실행한다(§15).
- **M1-2 추정치와의 일치:** `tools/compare_prepare`는 C++에서 탐욕적 매칭을 썼다([preprocess/compare_v1_1000.txt](preprocess/compare_v1_1000.txt)).
  - **C 대 B:** 쌍이 15,246쌍으로 같고, 모든 비율이 출력된 소수점 넷째 자리까지 같다.
  - **R 대 B:** 헝가리안 매칭이 한 쌍 더 찾았다(14,903 대 14,902). 프레임 107에서 탐욕적 매칭은 한 쌍(박스 16–14, IoU 0.618)을, 헝가리안 매칭은 두 쌍(15–14, IoU 0.606과 16–9, IoU 0.503)을 짓는다.
    - 분모가 커져서 R의 IoU ≥ 0.95 비율이 0.4697(14,902쌍 중 6,999쌍)에서 46.96%(14,903쌍 중 6,999쌍)로 바뀐다.
    - 나머지 비율은 소수점 넷째 자리까지 같다.
  - **텐서 값:** C++ 구현과 Python(numpy) 구현이 같은 값을 낸다.

## 의미

- **A5의 모든 지표에서, C와 B의 차이는 B가 허용하는 두 OpenCV 변형 사이의 차이보다 작다.** 후처리 작업량인 전체 박스 수도 B와 0.44% 안에서 같다.
- **등록 기준은 M1-2의 예측대로 실패한다(A5).** 255단계 중 약 2단계의 입력 차이에도 INT8 모델의 신뢰도는 최대 0.26까지 움직인다. 쌍의 3.6%는 0.10 넘게 차이 난다.
- **독립적인 검증이 아니다.**
  - A5의 기준은 같은 프레임에서 M1-2 추정치를 본 뒤에 정했다.
  - M1-4는 1,000프레임이 있는 유일한 영상에서, 등록된 매칭 알고리즘으로 그 비교를 다시 한 것이다.
  - [A8](../../prereg/AMENDMENTS.ko.md)은 A5의 기준을 정할 때 쓰지 않은 영상 ②, ③, ④로 하는 검사를 등록한다([아래](#홀드아웃-검사-a8)).
- **클래스별로는 bus와 stop sign에서 C가 B와 크게 다르다.**
  - **bus:** +14.65%다. R은 −1.27%다.
  - **stop sign:** C는 +72.64%, R은 −93.40%다. stop sign은 모든 변형에서 0.25 임계값 근처를 오간다.
  - 리포트는 이 값들을 전체 값과 함께 밝힌다.
- **현재 기준으로 §12 시작 전 §11의 관문은 통과했다.** `freeze-m1` 전에 남은 것:
  - 캘리브레이션과 열 확인(M1-3)
  - §3의 반복 재생 검사
  - A8의 홀드아웃 검사
  - 아직 정하지 않은 §14의 값

## 홀드아웃 검사 (A8)

실행 전에 [AMENDMENTS A8](../../prereg/AMENDMENTS.ko.md)에 등록했다. 아직 실행하지 않았다.

- **입력:** 영상 ②, ③, ④의 모든 프레임. 각각 752, 714, 948프레임으로 모두 2,414프레임이다. B, C, R은 이 영상들로 전처리나 추론을 한 적이 없다.
- **실행:** 보드에서 `tools/equivalence_holdout.sh`를 실행한다.
  - 각 영상의 SHA-256과 프레임 수를 확인한다.
  - 영상마다 M1-4와 같은 방식으로 `tools/equivalence_dump`를 실행한다.
  - 그다음 세 영상을 합쳐 `tools/equivalence_check.py --set`을 실행한다.
- **판정:** 합친 프레임에 A5의 여섯 조건을 적용한다. 영상별 결과도 보고한다.
- **결과가 어떻든** 비교 실행은 진행하고, 이 결과 때문에 바꾸는 것은 없다. 실패하면 리포트 요약에 적고, 모든 가설 판정에 'A5의 동등성은 영상 ①에서만 확인됐다'는 단서를 붙인다.
- **등록:** Release `amend-A8`. 검사는 그 `created_at` 뒤에 시작한다.

## 파일

| 파일 | 내용 |
|---|---|
| `b.jsonl`, `c.jsonl`, `r.jsonl` | PROTOCOL §1 항목을 담은 머리 줄, 이어서 프레임마다 번호, pts, 검출 `[class, score, x1, y1, x2, y2]` |
| `tensors.sha256` | `b.u8`, `c.u8`, `r.u8`(각 1,000 × 640 × 640 × 3바이트)의 해시. 판정 실행의 텐서는 릴리스 [data-equivalence-20261102T011123Z](https://github.com/eunkyo3/rk3588s-zero-copy/releases/tag/data-equivalence-20261102T011123Z)에 xz로 압축해 두었다. 나머지 두 실행의 텐서는 같은 내용이라 보관하지 않는다. |
| `env.txt` | 실행 전 `collect_env.sh` 출력 |
| `env.json` | 인자, 라이브러리 버전, 백엔드별 설명, 하네스 검사 |
| `dump.txt`, `dump.log` | 덤프의 출력과 stderr |
| `check.txt`, `check.json` | 판정 리포트와 그 수치 |

실행 시작 시각은 JSONL 머리 줄의 `start_time_utc`다. `env.txt`에는 `collect_env.sh`를 실행한 시각이 있다.
