# librkzc

이 저장소의 변형 C 경로(하드웨어 디코딩, RGA 레터박스, NPU 추론, 픽셀의 CPU 복사 없음)를 라이브러리로 만든 것이다. [docs/design/packaging.ko.md](../docs/design/packaging.ko.md)의 2단계부터 5단계에 해당한다. 경로를 벤치마크에서 분리했고, OpenCV가 필요 없으며, 벤치마크가 종료하던 자리에서 오류를 반환하고, 멈출 때까지 실행하며, 재연결하고, 검출 결과를 내준다.

**상태:** C++, C, 파이썬 인터페이스로 동작하는 검출기, 서비스 파일을 갖춘 프로그램, 그리고 이들을 설치하는 `.deb`가 있다. 설치 방법은 [docs/install.ko.md](../docs/install.ko.md)에 있다. CPU 시간이나 지연은 측정한 것이 없다.

## 사용

```cpp
#include <rkzc/rkzc.h>

rkzc::Config cfg;
cfg.model = "models/yolov8n_i8.rknn";
cfg.sources = {"rtsp://10.88.0.1:8554/ch1", "rtsp://10.88.0.1:8554/ch2"};

rkzc::Status st;
auto det = rkzc::Detector::open(cfg, &st);
if (!det) { std::fprintf(stderr, "%s\n", st.message.c_str()); return 1; }

det->on_frame([](const rkzc::Frame& f) {
    for (int i = 0; i < f.count; i++) {
        const rkzc::Detection& d = f.detections[i];   // x, y, w, h는 원본 프레임의 픽셀 단위
        std::printf("ch %d: %s %.2f\n", f.channel, rkzc::class_name(d.cls), d.score);
    }
});
det->on_event([](const rkzc::Event& e) { /* 소스가 열렸다, 끊겼다, 열 수 없다 ... */ });
det->start();
// ...
det->stop();
```

- **샘플링:** `every_nth_frame`장 중 한 장을 추론한다(기본 6: 30 fps 스트림에서 초당 5회, 벤치마크의 주 조건).
- **모델:** rknn_model_zoo가 내보낸 YOLOv8과 YOLOv10. 모델의 출력 형식을 보고 고른다. 임계값은 측정에 쓴 값으로 고정이다.
- **소스:** RTSP(TCP)의 H.264 또는 파일. 소스가 끝나거나, 실패하거나, 열리지 않거나, 열린 채 10초 동안 프레임을 주지 않으면 다시 연다. 대기 시간은 1초에서 시작해 프레임이 오지 않는 동안 30초까지 두 배씩 늘고, 프레임이 오면 1초로 돌아간다. 끝까지 재생한 파일은 그 채널을 끝내고, `loop_files`를 켜면 처음부터 다시 재생한다. 열리지 않는 파일은 스트림처럼 다시 시도한다.
- **콜백**은 라이브러리의 스레드에서 한 번에 하나씩 불린다. 콜백이 느리면 파이프라인이 밀리고, 샘플링된 프레임이 버려진다(`stats()`가 센다).

인터페이스는 [include/rkzc/rkzc.h](include/rkzc/rkzc.h)가 전부다. [examples/detect_jsonl.cpp](examples/detect_jsonl.cpp)는 검출 결과를 JSON 줄로 출력하는 예제다.

## C와 파이썬

- **C:** [include/rkzc/rkzc_c.h](include/rkzc/rkzc_c.h)는 같은 검출기를 일반 C 함수로 내놓는다. 같은 `librkzc.so` 안에 있다. `rkzc_open`, `rkzc_on_frame`, `rkzc_start`, `rkzc_stop`, `rkzc_close`다. 실패는 반환값으로 알리고, 이유는 호출한 쪽의 버퍼에 쓴다.
- **파이썬:** [python/rkzc](python/rkzc/__init__.py)는 `ctypes`로 C 인터페이스를 부른다. Python 3만 있으면 된다. 컴파일한 모듈도 NumPy도 필요 없다.

```python
import rkzc

def on_frame(frame):                      # 라이브러리의 스레드에서 한 번에 하나씩 불린다
    for d in frame.detections:            # x, y, w, h는 원본 프레임의 픽셀 단위
        print(frame.channel, d.name, round(d.score, 2), d.x, d.y, d.w, d.h)

with rkzc.Detector(["rtsp://10.88.0.1:8554/ch1"], "models/yolov8n_i8.rknn", on_frame=on_frame) as det:
    det.start()
    det.wait(60)                          # 초 단위. 기다리는 동안 Ctrl-C가 듣는다
```

- **라이브러리를 찾는 방법:** 아직 패키지가 없어서 모듈을 소스 트리에서 쓴다. `PYTHONPATH=lib/python`, `RKZC_LIBRARY=build-lib/librkzc.so.0`으로 지정한다(지정하지 않으면 로더 경로의 `librkzc.so.0`).
- **옵션**은 `rkzc::Config`의 것을 키워드 인자로 준다. `det.stats()`, `rkzc.check_model()`, `rkzc.check_source()`도 있다. 실패하면 라이브러리가 준 이유를 담아 `rkzc.Error`를 던진다.
- **콜백에서 난 예외**는 출력하고 `det.callback_errors`에 센다. 검출기는 계속 돈다. 라이브러리는 이 예외를 보지 못한다. 그 프레임은 추론된 것으로 세어지고, 예외를 던진 C++ 콜백과 달리 `FRAME_ERROR` 이벤트가 없다.
- **콜백 안에서는** `stats()`를 부를 수 있다. `start()`, `stop()`, `close()`, `wait()`는 거부된다.
- **시작한 검출기는 멈추거나 닫을 때까지 살아 있다.** 프로그램이 마지막 참조를 버려도 그렇다. 인터프리터가 끝날 때까지 돌고 있는 것은 그때 닫는다. 돌고 있지 않은 검출기는 참조를 버리는 즉시 해제된다.
- [python/examples/detect_jsonl.py](python/examples/detect_jsonl.py)는 C++ 예제와 같은 JSON 줄을 출력한다.

## 프로그램: `rkzc-detect`

그냥 돌리고 싶은 사람을 위한 프로그램이다. 설정 파일을 받아, 멈출 때까지 JSON 줄을 내보낸다(4단계).

```sh
rkzc-detect --config detect.toml --check    # 파일을 읽고, 실행할 때처럼 검출기를 열고, 소스를 하나씩 한 번 열어 본다
rkzc-detect --config detect.toml            # SIGTERM이나 Ctrl-C까지 실행한다
```

- **설정**은 작은 파일 하나다([dist/detect.toml](dist/detect.toml)이 주석 달린 예시다). 모델, 소스, 샘플링, 출력, 재연결 대기를 적는다. 형식은 TOML의 부분집합이고 라이브러리 없이 읽는다. 프로그램이 모르는 키는 줄 번호와 함께 오류가 된다.
- **출력**은 한 줄에 JSON 객체 하나다. stdout으로 내거나, 여러 클라이언트가 읽을 수 있는 Unix 소켓으로 낸다.

  ```json
  {"channel":0,"seq":12,"pts_us":400000,"time_ms":1795135300305,"width":1920,"height":1080,"detections":[{"class":0,"name":"person","score":0.8411,"x":408.60,"y":415.60,"w":104.73,"h":298.37}]}
  {"event":"source_lost","channel":0,"time_ms":1795135300456,"message":"..."}
  ```

  `x`, `y`, `w`, `h`는 원본 프레임의 픽셀 단위다. `time_ms`는 줄을 쓴 시점의 벽시계 시각이다. 소켓은 `nc -U /run/rkzc/detect.sock`으로 읽을 수 있다.
- **읽기를 멈춘 소켓 클라이언트는 버퍼가 차면(수백 줄) 끊는다.** 프로그램은 그 클라이언트를 기다리지 않는다. 읽는 쪽은 줄바꿈 없이 끝난 마지막 줄을 버려야 한다. `max_clients`(16)를 넘는 클라이언트는 바로 닫는다. stdout은 읽는 쪽을 기다리며, 읽는 쪽이 사라지면 프로그램이 끝난다.
- **소켓을 누가 읽을 수 있는지**는 `socket_group`과 `socket_mode`로 정한다. 예시는 `video` 그룹에 허용한다. 접속하려면 쓰기 권한 비트가 필요하다.
- **소스 URL에 든 사용자와 비밀번호**는 프로그램의 로그와 모든 출력 줄에서 `***`로 바뀐다. 설정 파일에는 그대로 들어 있다. 다른 사용자가 못 읽게 하는 방법은 예시 파일에 적었다.
- **종료 상태:** 멈췄거나 모든 소스가 끝나면 0, 실행 중 실패는 1, 쓸 수 없는 설정은 2다.
- **서비스로:** [dist/rkzc-detect.service.in](dist/rkzc-detect.service.in)은 `/etc/rkzc/detect.toml`로 프로그램을 실행한다. 실행할 때 만들어지는 사용자로 돌고, 경로의 장치를 소유한 `video`와 `render` 그룹에 넣는다. 소켓은 `/run/rkzc/detect.sock`이고 로그는 저널로 간다. 실패하면 다시 시작하지만 상태 2에서는 다시 시작하지 않는다. `cmake --install`은 라이브러리, 헤더, 프로그램, 서비스 파일, 예시를 설치한다. `/etc/rkzc/detect.toml`과 모델은 설치하지 않는다. 서비스 파일에 적히는 프로그램 경로는 configure할 때(`CMAKE_INSTALL_PREFIX`) 정해진다. 5단계의 패키지가 이 모든 일을 사용자 대신 할 예정이다.
- **없는 것:** MQTT, HTTP, 박스 그리기, 녹화, 재시작 없는 설정 다시 읽기. 앞의 네 가지는 이 줄들을 읽는 별도 프로그램으로 만들 수 있다.

## 빌드와 테스트

보드에서 `scripts/setup_board.sh`를 실행한 뒤에 한다(ffmpeg-rockchip, librknnrt, RKNN 헤더가 필요하다).

```sh
cmake -S lib -B build-lib \
    -DRKZC_TEST_MODEL=$PWD/models/yolov8n_i8.rknn \
    -DRKZC_TEST_VIDEO=/path/to/2_seconds.mp4 \
    -DRKZC_TEST_OBJECTS_VIDEO=/path/to/video_with_objects.mp4 \
    -DRKZC_DEMO_DETECT=$PWD/build/demo_detect
cmake --build build-lib -j4
(cd build-lib && ctest --output-on-failure)
```

`librkzc.so`, `rkzc-detect`(프로그램), `rkzc-check`(이 보드가 모델과 소스를 돌릴 수 있는지 확인), `rkzc-jsonl`(예제)이 만들어진다. 파이썬 테스트는 `python3`만 있으면 되고, 따로 설치할 것이 없다.

## 측정한 코드를 공유하는 방법

- **등록된 코드는 건드리지 않는다.** `src/`, `tools/`, `scripts/`, `tests/`, 루트 `CMakeLists.txt`는 `freeze-m3`와 같고, 다르면 `scripts/reproduce_m1.sh`가 실행을 거부한다. 그래서 라이브러리는 `lib/`의 별도 빌드이며, `bench_main`은 전과 똑같이 빌드된다.
- **같은 소스 파일을 다시 컴파일한다.** `lib/CMakeLists.txt`는 `../src`의 파일 여덟 개를 그대로 컴파일한다. 디코더 입력, NPU 컨텍스트, 슬롯 풀, 변형 C의 백엔드(RGA 호출과 dma-buf 슬롯), 후처리 세 가지다.
- **헤더 두 개를 include 경로로 바꿔 끼운다**(`lib/shim/`).
  - `core/util.h`: 벤치마크의 `die()`는 메시지를 찍고 종료하지만, 여기서는 예외를 던진다. 라이브러리가 이를 잡아 `Status`로 반환하거나 이벤트로 보낸다.
  - `preprocess/fd_cache.h`: 디코더 버퍼의 RGA 핸들 캐시가, 실행 중에 한 채널의 항목을 해제할 수 있다. 벤치마크는 입력을 한 번 열고 끝에서 해제한다. 검출기는 재연결하며, 재연결할 때마다 새 디코더와 새 버퍼가 생긴다.
- **파이프라인은 새로 썼다**(`src/detector.cpp`). `src/core/pipeline.cpp`를 따랐다. 단계, 큐, 슬롯 수, 정지 순서가 같고, 타임라인과 프레임별 기록이 없으며, 재연결과 콜백이 있다.
- **공개 헤더**는 FFmpeg, RGA, RKNN 헤더를 포함하지 않는다. 라이브러리가 내보내는 함수는 `rkzc::`와 C 인터페이스의 `rkzc_`뿐이고(표준 라이브러리의 약한 템플릿 인스턴스는 제외), `exit` 호출이 없다.

## 알려진 한계

- **모든 소스의 화면 비율이 같아야 한다.** 슬롯의 테두리는 한 번만 채우므로, 모든 프레임이 같은 영역으로 레터박스되어야 한다. 그렇지 않은 프레임은 `FrameError`와 함께 건너뛴다.
- **임계값은 고정이다**(신뢰도 0.25, NMS IoU 0.45 또는 최대 검출 300개). 전처리 스레드 두 개와 NPU 컨텍스트 세 개도 고정이다.
- **한 채널의 프레임 순서가 조금 뒤바뀔 수 있다.** NPU 워커 세 개가 따로 끝나기 때문이다. `Frame::seq`로 알 수 있다.
- **여는 데 실패하면, 실패한 단계가 쥐고 있던 것이 샐 수 있다.** RGA가 슬롯을 거부하면 그 슬롯의 버퍼와 매핑이, 출력 확인의 실행이 실패하면 거기서 쓰던 별도 RKNN 컨텍스트가 샌다. NPU나 커널이 실패해야 일어나는 일이다.
- **동작이 정의되지 않는 실패가 하나 있다.** 디코더가 DRM PRIME 프레임을 제공하지 않으면 `die()`가 FFmpeg 콜백 안에서 예외를 던진다. `h264_rkmpp`는 항상 DRM PRIME을 제공한다.
- **아래 라이브러리들**(MPP, RKNN, FFmpeg)**이 stderr에 직접 출력한다.**
- **재연결은 유선으로 연결한 RTSP 서버 하나(mediamtx)로 테스트했다.** 카메라, Wi-Fi, 패킷 손실로는 테스트하지 않았다. "확인한 것"의 표는 `ctest`가 아니라 수동 테스트의 결과다.
- **파이썬 콜백은 파이썬의 전역 잠금 아래에서** 한 번에 하나씩 실행되고, 라이브러리는 콜백이 끝나기를 기다린다. 콜백이 CPU 시간이나 프레임 손실에 주는 영향은 측정하지 않았다. 느린 콜백은 느린 C++ 콜백과 마찬가지로 프레임을 버리게 만든다. 다른 파이썬 스레드가 잠금을 쥐고 있으면 콜백도 기다리므로, 같은 프로세스에서 CPU를 많이 쓰는 파이썬 코드는 모든 콜백을 늦춘다.
- **파이썬 모듈은 아직 설치할 수 없다.** `pyproject.toml`이 없다. 5단계의 패키지가 시스템 경로에 놓을 예정이다.
- **라이브러리의 스레드는 프로그램의 신호를 막아 둔다**(스레드 자신이 일으키는 오류 신호는 제외). 그래서 파이썬의 Ctrl-C 처리기 같은 것은 프로그램 자신의 스레드에서 실행되고, 파이프라인의 읽기를 끊지 않는다. 끊긴 읽기가 실제로 문제를 일으켰을지는 테스트하지 않았다.
- **`rkzc-detect`의 설정은 TOML의 부분집합이다.** 실수, 날짜, 인라인 테이블, 중첩 섹션, 점으로 이은 키나 따옴표 친 키, 여러 줄 문자열, `0x`/`0o`/`0b` 정수, `\"` `\\` `\n` `\t` 외의 이스케이프가 없고, 배열에는 문자열만 넣을 수 있다. 임계값은 라이브러리가 고정하므로 설정할 수 없다.
- **서비스는 패키지가 아니라 테스트용 경로에 설치해서 돌렸고,** M3의 이미지 하나에서만 확인했다. 실행할 때 만들어지는 사용자로 돌며, 그래서 시스템이 읽기 전용으로 보이고, 홈 디렉터리에 접근할 수 없고, 전용 `/tmp`를 쓴다. 그 이상의 격리는 하지 않았다. 서비스에서 모델을 두는 자리(`/var/lib/rkzc`)는 테스트에서 쓰지 않았다.
- **상태 2는 일시적인 원인이어도 서비스를 완전히 멈춘다.** 그 순간 메모리가 모자라 모델을 못 올린 경우에도 다시 시도하지 않는다.
- **아래 라이브러리들이 소스 URL을 직접 출력할 수 있다.** 접속할 수 없는 URL로 한 테스트에서는 출력하지 않았다. 다른 종류의 실패는 시험하지 않았다.
- **stdout에서, 읽는 쪽이 남아 있으면서 읽기를 멈추면** 프로그램이 붙잡힌다. 그러면 깨끗하게 멈추지도 못하고, systemd에서는 20초 뒤에 강제 종료된다. 소켓에는 이런 경우가 없다.
- **소켓 클라이언트 하나는 파일 디스크립터 하나와 커널 메모리 최대 약 400 KiB를 쓰고,** 모든 줄은 검출기의 콜백 안에서 모든 클라이언트로 보내진다. 클라이언트 수를 제한하는 이유다.
- **`stop()`에서는, 이미 전처리된 프레임을 추론하는 동안 디코더가 먼저 닫힌다.** 벤치마크는 파이프라인이 비워질 때까지 입력을 열어 둔다. 전처리를 기다리던 프레임은 먼저 통과시키므로, 디코더가 닫힐 때 그 디코더의 버퍼를 쥔 프레임은 없다.
- **측정한 구성과 세 가지가 다르다.** `-fPIC`와 숨김 가시성(hidden visibility)으로 컴파일한다. CPU 고정을 하지 않는다(`bench_main`은 프로세스를, 따라서 MPP, FFmpeg, librknnrt의 스레드까지 A76 코어 4~7에 고정한다). 콜백, 좌표 변환, 감시 스레드가 추가됐다. 이것들이 CPU 시간이나 지연을 어떻게 바꾸는지는 재지 않았다. 벤치마크와 같은 배치를 원하는 프로그램은 `Detector::open` 전에 스스로 고정하면 된다.

- **`rkzc-detect`**(2026-11-20, 같은 보드, 모델, 영상):
  - **설정 읽기와 출력의 문자열 함수:** 50가지 경우를 확인했다. 그중 39개는 거부되어야 하는 파일이고, 각각 예상한 이유가 나왔으며 35개는 줄 번호까지 확인했다(키가 빠진 경우는 줄 번호가 없고, 너무 큰 정수는 이유로 확인한다). 함께 넣은 예시 파일은 읽힌다. 같은 테스트가 PC에서 주소·미정의 동작 sanitizer를 켠 채로도 통과했다.
  - **종료 상태:** 인자가 없을 때, 설정 파일이 없거나 키를 잘못 썼을 때, 모델이 없을 때, 소켓을 만들 수 없을 때, 없는 그룹을 지정했을 때 2가 나왔다. `--check`는 올바른 파일에 0을 냈고, 소스가 없을 때와 후처리가 모델에 맞지 않을 때 1을 냈다. 뒤의 경우를 실제로 실행하면 2로 거부됐다.
  - **stdout:** 한 번 재생한 파일에서 형식이 맞는 프레임 줄 10개와 이벤트 줄 2개가 나왔고, 프로그램은 상태 0으로 종료했다. 이벤트와 빈 프레임을 끄면, 검출이 있는 프레임 하나만 줄로 나왔다. 읽는 쪽이 파이프를 닫자 상태 1로 종료했다.
  - **URL의 비밀번호:** 접속할 수 없는 소스 `rtsp://someone:hunter2@...`를 넣었을 때 오류 줄 10개와 프로그램의 로그에는 `rtsp://***@...`로 나왔고, 비밀번호는 출력 어디에도 없었다.
  - **소켓:** 소켓 파일은 지정한 모드와 그룹을 가졌다. 같은 소켓으로 띄운 두 번째 프로그램은 거부됐다. 사라진 프로그램이 남긴 소켓 파일은 시작을 막지 않았다. 클라이언트 두 개가 각각 두 채널의 형식이 맞는 줄을 검출과 함께 받았다. `max_clients = 3`에서 세 번째 클라이언트는 줄을 받았고 네 번째는 한 줄도 못 받고 닫혔다. 한 번도 읽지 않는 클라이언트는 그것만 끊겼고, 그동안 나머지 둘은 601줄을 읽었다. SIGTERM을 받자 0.16초 만에 상태 0으로 종료했고 소켓 파일은 지워졌다.
  - **서비스로:** 테스트를 위해 `/opt/rkzc-test`에 설치했다가 지웠다. 설정 파일은 `root:video 0640`으로 두고 소켓 설정은 예시 그대로 썼다. 서비스가 시작됐고, 실행할 때 만들어진 사용자와 그룹 44, 992(`video`, `render`)로 돌았다. 사용자 `pi`가 `/run/rkzc/detect.sock`(`video`, `0660`)에서 두 채널의 프레임 줄 30개(검출 498개)를 읽었다. `systemctl stop`은 0.19초 만에 상태 0으로 끝났다.   - **보드 기본 이미지의 chroot에서**(`packaging/test_clean_image.sh`. 이 이미지에는 FFmpeg 빌드도 librknnrt도 없다): 네트워크 없이 한 `dpkg -i`는 성공했고 `rkzc-fetch-runtime`을 안내했다. `apt-get install`은 다른 패키지를 설치하지 않았고 librknnrt를 내려받았다. 프로그램이 필요한 라이브러리는 모두 `/opt/rkzc/lib`에서 찾아졌다. `rkzc-fetch-model`이 모델을 받았다. `rkzc-check`가 모델을 NPU에 올리고 파일을 디코딩했다. `rkzc-detect`는 설치된 설정을 읽었고, 파일을 재생해 프레임 줄 10개를 냈다. 파이썬 모듈과 예제도 같은 10프레임을 냈다. `apt-get remove` 뒤에는 설정과 모델이 남아 있었고, `apt-get purge` 뒤에는 전에 없던 파일이 하나도 남지 않았다.
  - **실제 보드에서:** `apt install`은 패키지 하나만 추가했다. 서비스를 활성화한 상태에서 사용자 `pi`가 소켓에서 두 채널의 프레임 줄 30개를 `nc`와 파이썬으로 읽었다. 설치된 헤더로 컴파일한 C 프로그램이 실행됐다. `systemctl stop`은 0.17초 만에 상태 0으로 끝났다. 서비스가 도는 중에 purge하면 서비스가 멈췄다. 그 뒤 패키지 목록과 `/etc`, `/opt`, `/usr`, `/var/lib` 아래의 파일은 전과 같았다.
  - **설치 거부:** PC에서 설치 전 스크립트는 메시지와 함께 상태 1로 끝났고, `RKZC_FORCE=1`에서는 상태 0으로 끝났다.
